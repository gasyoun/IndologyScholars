# PLAN — Sanskrit community lenses around Roerich and Zograf, 1990–2026

**Goal:** prepare a major Russian-language revision of the Roerich/Zograf
article in which the two conference series remain the principal object of
study, while nagari, ORS/VK, INDOLOGY-L, and Bharatiya Vidvat Parishat (BVP)
provide four bounded comparison lenses. The quantitative core is 2005–2025;
1990–2004 is digital prehistory, pre-1990 material is historical context, and
2026 is always reported as an incomplete update.

The first execution span does **not** rewrite the submitted article. It creates
a frozen comparison package, a validity report, figures, a quote register, and
a detailed Russian outline for the revision. The submitted text remains an
immutable baseline until those gates pass.

**Central claim:** the corpora do not form one flat population. They make
different parts of Sanskrit scholarly life observable:

1. Roerich and Zograf show formal conference selection and public research
   presentation in a Russia-centred field.
2. nagari shows Russian-language learning, textual practice, resource exchange,
   and internal question-and-answer.
3. ORS/VK shows Russian public curation, outreach, and measurable engagement.
4. INDOLOGY-L shows an overwhelmingly Western-centred international
   professional Indology forum, while retaining its small Russian and Indian
   participation as observed data.
5. BVP shows the principal India-centred Sanskrit scholarly forum selected for
   this study.

The phrases “overwhelmingly Western-centred” and “principal India-centred hub”
are corpus-selection premises grounded partly in the author's long
participation and expert judgment. They are not estimates of all Western or
Indian Sanskrit scholarship. Actual author affiliations and cross-list
participation must still be measured.

## Prior-art verdict

**Verdict: PARTIAL — extend, do not rebuild.**

- The conference corpus already owns stable presentation IDs, a normalized
  SQLite database, authority IDs, Gumilev `argument_level`, thematic and meso
  classifications, provenance reports, and reproducible article snapshots.
- nagari already owns mbox ingestion, FTS5, messages, threads, attachments,
  members, topic rules, Markdown export, and privacy/rights controls.
- ORS/VK already owns API/XLSX ingestion, native post IDs, attachments,
  engagement metrics, topic tables, gallery/search exports, and a static page.
- IndologyArchiveAtlas is the canonical INDOLOGY-L repository. The existing
  one-way feed into IndologyScholars must be generalized; the archive itself
  must not be copied back into this repository.
- Renou cross-site outputs already exist, but their semantic precision is not
  publishable until the existing 150-item gold review is adjudicated.
- No existing component supplies a common observation schema, function
  taxonomy, cross-lens identity review, quote register, synchronized manifests,
  or BVP adapter. Those are the genuine new assets.

## ACL standards adopted

ACL Anthology contributes **standards**, not records:

1. stable IDs that never depend on mutable titles, names, or classifications;
2. explicit `series → event/container → record` hierarchy without forcing
   publication-shaped IDs onto messages or posts;
3. separation of a name as attested on a record from a resolved person;
4. authoritative source records separated from controlled vocabularies and
   rebuildable derived outputs;
5. machine-readable schemas, reference integrity, full-corpus loading,
   deterministic serialization, and round-trip validation;
6. source checksums, acquisition dates, revision status, and pinned build
   manifests;
7. structured, evidence-bearing corrections rather than silent edits.

Primary references:

- [ACL Anthology identifiers](https://aclanthology.org/info/ids/)
- [ACL Anthology names policy](https://aclanthology.org/info/names/)
- [ACL Anthology corrections](https://aclanthology.org/info/corrections/)
- [ACL Anthology detailed repository guide](https://github.com/acl-org/acl-anthology/blob/master/README_detailed.md)
- [ACL Anthology schema](https://github.com/acl-org/acl-anthology/blob/master/data/xml/schema.rnc)
- [ACL Anthology Python guide](https://acl-anthology.readthedocs.io/python-dev/)

The plan explicitly does **not** copy ACL's paper ID grammar, XML/YAML split,
PDF authority rule, name decomposition, licensing assumptions, rolling-main
updates, or static-site machinery.

## Autonomy contract

### On ambiguity

Use the pinned default, record it in the build report, and continue:

- uncertain identity → leave `person_id` empty and emit a review row;
- uncertain classification → use `unknown`, or `not_applicable` for an axis
  that does not apply; never force a confident label;
- ambiguous crosswalk → retain the native label and map it as `related` or
  `unmapped`, not `exact`;
- incomplete BVP enumeration or fetch → preserve the crawl ledger, label every
  result with measured coverage, suppress completeness-dependent claims, and
  continue the other four adapters;
- unstable or contextless quotation URL → omit the quotation and log the
  reason; do not paraphrase it;
- conflicting 2025/2026 boundary → assign by source timestamp and keep all
  2026 records in the partial snapshot.

### Stop conditions

Halt only the affected adapter, preserve diagnostics, and continue independent
work when:

- a source requires credentials or access not already present;
- a bulk-acquisition method conflicts with source terms, robots, or a rights
  ruling;
- a source count differs from its frozen baseline by more than 1% without an
  explainable refresh;
- a stable source ID collides;
- serialization changes existing canonical IDs;
- source text or contact information would be exposed outside the approved
  quote policy.

Halt the whole run if the shared schema cannot preserve a lens's native unit,
if the submitted PPV article would be overwritten, or if a command would
commit, push, publish, merge, or delete user data.

### Authority and fence

Authorized:

- read public/local sources;
- create local derived metadata, review queues, validation reports, figures,
  and a new Russian revision outline;
- use exact public quotations with source context and named authors;
- make reversible edits inside an isolated worktree.

Forbidden in this span:

- commit, push, PR, merge, deploy, publish, or mint a handoff whose tool pushes;
- overwrite `article/ppv_submission_article.md`;
- modify canonical IndologyArchiveAtlas records from this repository;
- publish raw nagari/BVP/INDOLOGY attachments or private exports;
- publish raw BVP captures, attachments, or unrelated contact/signature data;
- call a BVP scrape complete without a reconciled listing denominator, zero
  unexplained gaps, and a frozen manifest;
- expose email addresses, telephone numbers, postal addresses, API tokens, or
  unrelated signature blocks;
- automatically merge fuzzy identities;
- use 2026 partial records in 2005–2025 trend estimates;
- present BVP or INDOLOGY-L as a census of India or “the West”.

## Autonomy-readiness gate

**Verdict: PASS for execution content; external wiring deferred by the explicit
no-push fence.**

Every Wave 1 deliverable has an architecture contract, ordered file-level
steps, an acceptance criterion, and identified risks. No blocking
implementation fork survives. The BVP acquisition uncertainty has a pinned,
coverage-measured scraping path that preserves progress without manufacturing
full-corpus statistics.
Existing assets are consumed rather than rebuilt.
