**Цель:** +20 имён, общая полнота: 80% → 90%

**Почему не собрано:**
Вики-категории `Индологи России` и `Индологи СССР` не включают индологов Украины, Литвы, Латвии, Грузии, Казахстана и др. постсоветских стран — у них свои национальные категории.

**Метод — через en.wikipedia.org API (работает):**

```python
# 1. Поиск через английскую вики (API открыт)
params = {
    "action": "query",
    "list": "search",
    "srsearch": "incategory:Ukrainian_indologists",
    "format": "json",
}
# 2. Для каждой найденной страницы получить langlinks к русской вики
params = {
    "action": "query",
    "pageids": "...",
    "prop": "langlinks",
    "lllang": "ru",
    "format": "json",
}
```

- `Category:Ukrainian_indologists`
- `Category:Lithuanian_indologists`
- `Category:Latvian_indologists`
- `Category:Georgian_indologists`

## Этап 3: Институциональный скрейпинг (УЗКОЕ МЕСТО)

### 3.0 Диагноз

**Проблема:** институциональные сайты (ivran.ru, rggu.ru, hse.ru) рендерят контент через JavaScript. Простой HTTP-запрос возвращает страницу-заглушку с пустыми `<div>`-контейнерами, которые наполняются через AJAX/XHR.

**Пример (ivran.ru/sotrudniki):**
```
HTTP GET → 79 КБ HTML:
├── <div class="letter"><h2>В</h2>
│   └── <p><a href="/persons/EugeniaVanina">Ванина Е.Ю.</a></p>  ← ИМЯ есть
│   └── ... ещё 10 имён
└── <script src="..."> ← JS-рендер загружает остальной контент

HTTP GET → ivran.ru/persons/EugeniaVanina:
├── 58 КБ HTML шаблона (шапка, футер, меню, highslide JS)
├── <title>Российский индологический архив</title>  ← общий заголовок
└── <div id="content"> ← пустой! Персональные данные грузятся через JS
```

**Вывод:** Для `ivran.ru` имена сотрудников на странице `/sotrudniki` есть в HTML (алфавитный список с `<a>`-ссылками). Но персональные данные (должность, отдел, специализация) на странице `/persons/*` загружаются через JavaScript и недоступны через HTTP GET.

### 3.1 Вариант A: Поиск JSON API (быстрый)

**Гипотеза:** Drupal-сайты (а ivran.ru — это Drupal) часто имеют JSON:API endpoint.

**Что искать в исходном коде `/sotrudniki`:**
```bash
# Искать в HTML страницы:
grep -o 'jsonapi\|/api/\|/rest/\|fetch(\|$.ajax' html_source.txt
```

**Пример Drupal JSON:API:**
```
GET https://www.ivran.ru/jsonapi/node/person?filter[department]=130
→ JSON с полями: title, field_position, field_department, field_bio
```

**Если endpoint найден:**
- Парсер: 30 строк Python → 15 минут работы
- Покрытие: ИВ РАН (~20 индологов)

**Если endpoint НЕ найден:**

### 3.2 Вариант B: Playwright / headless Chrome (средний)

```python
# pip install playwright
# playwright install chromium

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch()
    page = browser.new_page()
    page.goto("https://www.ivran.ru/sotrudniki")
    page.wait_for_selector(".person-card")  # ждать JS-рендер
    html = page.content()  # получить полный отрендеренный HTML
    # парсить как обычно
```

**Плюсы:**
- Даёт полный HTML после JS-рендера
- Работает для любого сайта (не только ivran.ru)

**Минусы:**
- Требует установки Chromium (~300 МБ)
- Медленнее: ~3-5 секунд на страницу
- Может детектироваться антибот-защитой

**Оценка трудозатрат:** 2-3 часа на написание + отладку

### 3.3 Вариант C: ИВР РАН — text-версия (уже работает)

**Особенность:** `orientalstudies.ru` отдаёт список сотрудников в text-формате через `webfetch`.

**Что доработать:**
- Извлечь ВСЕ ссылки на персональные страницы
- Для каждой — получить text-версию bio

**Трудозатраты:** 30 минут (доработка существующего парсера)

## Этап 4: Устранение ограничений API

### 4.1 Варианты обхода блокировки ru.wikipedia.org/api.php

| # | Метод | Статус |
|---|-------|--------|
| 1 | HTML-обход `w/index.php?search=` | ✅ Реализован по-настоящему (`search_via_html()` в expand_…py) |
| 2 | `ru.m.wikipedia.org/w/api.php` | ❌ Протестирован — тоже недостижим (мобильный поддомен не помогает) |
| 3 | `en.wikipedia.org/w/api.php` + `langlinks` | ✅ **Реализован — `enwiki_bridge.py`** (основной путь, RKN-устойчив) |
| 4 | `web.archive.org` кеш категорий | 🔴 Не тестировался |
| 5 | Tor / VPN / прокси | 🔴 Не тестировался |

**Приоритет:** #3 готов и стал основным. ru-домен (API и мобильный) недостижим;
для русскоязычных инфобоксов нужен доступ к ru.wikipedia-**статьям** (есть только
из РФ).

### 4.2 Стабилизация Wikidata

| # | Метод | Статус |
|---|-------|--------|
| 1 | `Special:EntityData/Qxxx.json` (REST) | ✅ Стабильный |
| 2 | `w/api.php?action=wbgetentities` | 🟡 Через раз |
| 3 | `query.wikidata.org/sparql` | 🔴 502 Bad Gateway |

**Стратегия:** использовать ТОЛЬКО REST-эндпоинт (`Special:EntityData/`). Для массовых запросов — батчинг по 5 Q-ID.
