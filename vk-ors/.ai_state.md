same real-world community): turn the VK export `vk_posts_all.xlsx`
into (a) a searchable SQLite+FTS5 DB and (b) the same four-layer analysis
nagari uses, adapted for a flat wall export (no threads/authors, but rich
engagement counters). Wave-1 adds gallery + faceted search + engagement tiers.

## 🧠 Dev Notes & Hypotheses

- No thread/author structure in the source — one publishing account (the VK
  page), so the analysis layers replace nagari's Layer 2 (threads & reply
  network) with an **engagement** layer (top posts by likes/reposts, view→
  like/repost/comment conversion by year) instead.
- `#bookzealots` (313) is the dominant hashtag — the page's own tag for book/
  dictionary-announcement posts; `санскрит` (197) and `читаем_с_орс` (66,
  reading-group sessions) are the next most common.
- Devanagari term frequency is dominated by commentary-apparatus vocabulary
  (प्रतिपदार्थः, अन्वयः, पदविभागः — same fingerprint as nagari's IAST layer),
  consistent with both venues serving the same reading-group method.
- Raw xlsx, `attachments_raw.json`, and built DB are gitignored as regenerable
  build artifacts — repo hygiene, not privacy (public page, unlike nagari).
- Parent-repo `.env` holds `VK_*` (not `vk-ors/.env`); `fetch.py` `load_dotenv()`
  only sees CWD — when running from `vk-ors/`, load parent env first.
- Wave-1 without re-fetch yields gallery=0 (needs `attachments_raw.json` from
  current `fetch.py`); always re-run full chain after a code pull that changes
  attachment handling.
