# vk_ors_archive — архив стены «Общество ревнителей санскрита» ВКонтакте (2015–2026)

Воспроизводимый разбор экспорта публичной стены [vk.com/wall-88831040](https://vk.com/wall-88831040)
в поисковую базу + аналитику, тем же методом, что и
[nagari/nagari_group_archive](https://github.com/gasyoun/IndologyScholars/blob/main/nagari/README.md)
(закрытая гуглгруппа того же сообщества), но источник здесь проще: один
Excel-экспорт постов (без тредов и без имён авторов — публикует один аккаунт
страницы), зато с полными счётчиками вовлечённости (лайки/репосты/комментарии/
просмотры), которых у писем не было.

### Четыре слоя анализа

1. **Хронология и активность** — посты по годам и месяцам, суммы и средние
   лайков/репостов/комментариев/просмотров, тепловая карта год×месяц.
2. **Вовлечённость** — топ постов по лайкам и по репостам, тренд конверсии
   просмотр→лайк/репост/комментарий по годам.
3. **Темы и хэштеги** — таксономия тем по ключевым словам над текстом поста
   (словарь/учебник/книга/pdf/шрифт/текст/лингвистика/событие), собственные
   хэштеги страницы (`#bookzealots`, `#читаем_с_орс`, …), частотные термины.
4. **Санскрит и вложения** — частоты деванагари и IAST, инвентарь типов
   вложений (photo/doc/link/video/audio/poll), посты с книжными вложениями
   (doc + книжная/словарная лексика в тексте).

## Запуск

Зависимости: `openpyxl` (стандартная библиотека для SQLite с FTS5 не нужна доп. пакетов).

```sh
cd vk-ors
python -m vk_ors_archive.ingest      # xlsx → SQLite (data/vk_ors.db)
python -m vk_ors_archive.insights    # 4 слоя → data/processed/*.csv + data/site_data.json
python -m vk_ors_archive.page        # self-contained HTML → site/index.html
python -m vk_ors_archive.ingest --limit 300   # быстрая проверка разбора
```

Сырой экспорт (`vk_posts_all.xlsx`) читается из корня `vk-ors/` и
**никогда не изменяется**.

## Публикация

Публичная страница (не закрытая группа — третьих лиц как авторов сообщений
нет, автор поста один — аккаунт страницы). Тем не менее сырой xlsx и собранная
БД — под `.gitignore` как регенерируемые build-артефакты (репо-гигиена, не
приватность); коммитятся только код конвейера и производные CSV/JSON.
Как и для nagari, любая будущая HTML-страница/публикация проходит
`/publish-safety-check` перед выкладкой.
